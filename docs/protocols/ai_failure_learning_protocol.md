Generated: 2026-05-26T10:02:27Z

## Purpose

This protocol turns failed repo evolution attempts into durable repository memory. The goal is not to avoid all failures; the goal is to prevent repeated failures by converting each failure into a compact operating rule.

## Rule

A failed patch is not complete until the repair includes:

1. a minimal technical fix,
2. full validation rerun,
3. a lesson in the root README AI Failure Learning Ledger,
4. affected mini README updates when local routing or repair discipline changes,
5. a release note or report if the failure affected a public checkpoint.

## Validation Boundary

RCC-N validates navigation.
Architecture validation checks contracts.
Unit tests validate executable expectations.
Benchmarks validate local runtime behavior.
None of these independently validate silicon, products, manufacturing, process-node equivalence, or universal laws.

## Current v0.3.2 Lessons

- Compile and import checks are mandatory for runtime patches.
- PowerShell code-generation can inject escape residue; generated Python must be compiled.
- Run IDs must be collision-proof before benchmarks are trusted.
- Completion status must not be written as a success seal after validation failure.
